How to read the score
Solves per million tokens leads deliberately. Solving more raises it, spending more tokens lowers it, and a solution the judge dislikes counts for less than a clean one. It is the only cost signal every provider reports, which is why it leads rather than dollars.

Score is those four parts scaled against the best run on this page and then weighted, so it is only meaningful within one comparison and it moves when runs are added or the set is changed.

Effectiveness carries the most weight on purpose: a cheap model that does not fix the bug is worth nothing.

Where a row says some solved cases were not judged, the quality figure rests on fewer cases than the run solved. A run with no token or cost data, such as the human-patch reference, scores zero on those parts rather than being left out.

Cases per hour is 3600 divided by the median case's agent time — an extrapolation from one case, not an observed throughput, and the median is taken over every case the run attempted rather than the ones it fixed. It is the weakest column here and carries the least weight. It was labelled "Fixes per hour", which is neither.
